# Store API on PostgreSQL

The back office of a small online store: categories, products, customers, suppliers, and
warehouses, stored in PostgreSQL so the data survives a restart.

## Storage

- `DATABASE_URL` is a PostgreSQL connection URL, for example
  `postgres://user:password@localhost:5432/store?sslmode=disable`. The database exists but may be
  empty: the service creates its tables when they don't exist yet.
- Everything must be stored in that database: after the service is stopped and started again
  with the same `DATABASE_URL`, everything is still there.

## Resources

Every item has these fields, set by the server:

| Field        | Type   | Rules                                                 |
|--------------|--------|-------------------------------------------------------|
| `id`         | string | Generated by the server, unique                       |
| `created_at` | string | RFC 3339 timestamp, set by the server when created    |
| `updated_at` | string | RFC 3339 timestamp, set by the server on every change |

and its own fields:

**Category** (`/categories`)

| Field         | Type   | Rules                                         |
|---------------|--------|-----------------------------------------------|
| `name`        | string | Required, not blank                           |
| `description` | string | Optional; defaults to `""` when omitted       |

**Product** (`/products`)

| Field         | Type    | Rules                                               |
|---------------|---------|-----------------------------------------------------|
| `name`        | string  | Required, not blank                                 |
| `sku`         | string  | Required, not blank                                 |
| `price`       | number  | 0 or more; defaults to 0 when omitted               |
| `in_stock`    | boolean | Defaults to `false` when omitted                    |
| `category_id` | string  | Required; must be the ID of an existing category    |

**Customer** (`/customers`)

| Field   | Type   | Rules                                                           |
|---------|--------|-----------------------------------------------------------------|
| `name`  | string | Required, not blank                                             |
| `email` | string | Required; must contain exactly one `@` with text on both sides  |

**Supplier** (`/suppliers`)

| Field     | Type   | Rules                                   |
|-----------|--------|-----------------------------------------|
| `name`    | string | Required, not blank                     |
| `country` | string | Required, not blank                     |
| `phone`   | string | Optional; defaults to `""` when omitted |

**Warehouse** (`/warehouses`)

| Field      | Type    | Rules                                  |
|------------|---------|----------------------------------------|
| `name`     | string  | Required, not blank                    |
| `city`     | string  | Required, not blank                    |
| `capacity` | integer | 0 or more; defaults to 0 when omitted  |

## Endpoints

Each resource, at its path (for example `/categories`), has:

| Method and path           | Success                      | Errors              |
|---------------------------|------------------------------|---------------------|
| `POST /<items>`           | `201` with the new item      | `400`, `422`        |
| `GET /<items>`            | `200` with a page of items   | `400`               |
| `GET /<items>/{id}`       | `200` with the item          | `404`               |
| `PUT /<items>/{id}`       | `200` with the item          | `400`, `404`, `422` |
| `PATCH /<items>/{id}`     | `200` with the item          | `400`, `404`, `422` |
| `DELETE /<items>/{id}`    | `204` with no body           | `404`, `409`        |

and the service has `GET /health`, which responds `200`.

- `POST` and `PUT` take the resource's own fields. `PUT` replaces them all, so the same rules
  apply as for `POST`.
- `PATCH` changes only the fields present in the body; the result must still follow the rules.
- A product whose `category_id` isn't an existing category is a `422`.
- Deleting a category that still has products is a `409`; the category is kept.

## Conventions

- Request and response bodies are JSON.
- Errors respond with a JSON body `{"error": "<message>"}` and the status code:
  `400` for a body that isn't valid JSON or an invalid query parameter, `404` when no item has
  the ID, `409` for the conflict described above, `422` when the data breaks a rule above.
- Lists: `GET /<items>?limit=<n>&offset=<n>` responds with
  `{"items": [...], "total": <number of items>, "limit": <limit used>, "offset": <offset used>}`,
  oldest first. `limit` defaults to 20 and larger values than 100 are treated as 100; `offset`
  defaults to 0. A negative or non-numeric `limit` or `offset` is a `400`.
