# Products API

A service that manages a product catalog. Data may be kept in memory.

## Product

| Field        | Type    | Rules                                                          |
|--------------|---------|----------------------------------------------------------------|
| `id`         | string  | Generated by the server, unique                                |
| `name`       | string  | Required; 1 to 100 characters after trimming surrounding spaces |
| `price`      | number  | Required to be 0 or more; defaults to 0 when omitted            |
| `in_stock`   | boolean | Defaults to `false` when omitted                               |
| `created_at` | string  | RFC 3339 timestamp, set by the server when created             |
| `updated_at` | string  | RFC 3339 timestamp, set by the server on every change          |

## Endpoints

| Method and path          | Success                       | Errors           |
|--------------------------|-------------------------------|------------------|
| `POST /products`         | `201` with the new product    | `400`, `422`     |
| `GET /products`          | `200` with a page of products | `400`            |
| `GET /products/{id}`     | `200` with the product        | `404`            |
| `PUT /products/{id}`     | `200` with the product        | `400`, `404`, `422` |
| `PATCH /products/{id}`   | `200` with the product        | `400`, `404`, `422` |
| `DELETE /products/{id}`  | `204` with no body            | `404`            |
| `GET /health`            | `200`                         |                  |

- `POST` and `PUT` take `name`, `price`, and `in_stock`. `PUT` replaces all three, so the same
  rules apply as for `POST`.
- `PATCH` changes only the fields present in the body; the result must still follow the rules.

## Conventions

- Request and response bodies are JSON.
- Errors respond with a JSON body `{"error": "<message>"}` and the status code:
  `400` for a body that isn't valid JSON or an invalid query parameter, `404` when no item has
  the ID, `422` when the data breaks a rule above.
- Lists: `GET /products?limit=<n>&offset=<n>` responds with
  `{"items": [...], "total": <number of products>, "limit": <limit used>, "offset": <offset used>}`,
  oldest first. `limit` defaults to 20 and larger values than 100 are treated as 100; `offset`
  defaults to 0. A negative or non-numeric `limit` or `offset` is a `400`.
